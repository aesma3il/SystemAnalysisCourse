## 6. Fundamental Concepts Refresher

### What is a Computer?
A computer is an electronic device that accepts data as input, processes that data according to programmed instructions, produces information as output, and stores data and information for future use.

### Input
Input is the raw data or instructions that are entered into a computer system for processing. It represents the information that flows into the system from external sources.

### Process
Process is the series of operations or transformations performed on input data to convert it into meaningful output. It involves calculations, comparisons, sorting, filtering, and other logical operations.

### Output
Output is the processed information produced by a computer system after processing input data. It represents the results presented to users in a meaningful format.

### Storage
Storage is the component of a computer system that retains data, information, and instructions for future use. It includes primary storage (memory/RAM) and secondary storage (hard drives, SSDs, databases).

## 7. Business & Data Concepts

### What is a Business?
A business is an organization or economic entity that provides goods or services to customers in exchange for monetary compensation, with the primary goal of generating profit and creating value for its stakeholders.

### Data vs Information vs Knowledge vs Wisdom

| Concept | Definition |
|---------|------------|
| **Data** | Raw, unprocessed, unorganized facts, figures, symbols, or events that have no meaning or context on their own. |
| **Information** | Data that has been processed, organized, structured, or presented in a meaningful context to make it useful, relevant, and valuable for decision-making. |
| **Knowledge** | The understanding, awareness, and expertise gained from analyzing and interpreting information. It represents the application of information combined with experience, context, and insight. |
| **Wisdom** | The ability to apply knowledge, experience, and good judgment to make sound decisions, solve complex problems, and evaluate outcomes. It represents the highest level of understanding. |

**The DIKW Pyramid (Data → Information → Knowledge → Wisdom):**

| Level | Description | Example (Rental Platform) |
|-------|-------------|---------------------------|
| Data | Raw facts | Apartment ID: A101, Price: 500, Date: 2024-05-01 |
| Information | Processed, meaningful | Total apartments rented in May: 25 apartments |
| Knowledge | Understanding patterns | Apartment rentals increase by 40% during summer months |
| Wisdom | Informed decision-making | Invest in more apartments before summer and offer seasonal discounts |

## 8. Systems Thinking

### What is a System?
A system is a set of interrelated, interacting, or interdependent components that work together as a unified whole to achieve a common goal or objective.

### Components of a System

| Component | Description |
|-----------|-------------|
| **Input** | The resources, data, or materials that enter the system |
| **Process** | The transformations, operations, or activities that convert inputs to outputs |
| **Output** | The results, products, or information produced by the system |
| **Feedback** | Information about system performance used to adjust or control the system |
| **Control** | The mechanisms that regulate and coordinate system activities |
| **Environment** | Everything outside the system that influences or is influenced by it |
| **Boundary** | The line that separates the system from its environment |
| **Interface** | The points where the system interacts with other systems or users |

## 9. Information Systems

### Introduction to Information Systems

**Definition:** A set of interrelated components that collect, process, store, and provide information to support business tasks.

### Key Characteristics:
- Includes people, processes, and technology
- Transforms data → information → knowledge

## 10. Components of Information Systems

| Component | Description |
|-----------|-------------|
| **People** | Users, managers, IT staff, analysts who interact with the system |
| **Processes** | Procedures, rules, workflows that govern system operation |
| **Data** | The raw facts stored, processed, and managed by the system |
| **Technology** | Hardware, software, networks, databases that enable the system |

## 11. System Analyst Role

### Responsibilities of a System Analyst

| Responsibility | Description |
|----------------|-------------|
| **Requirement Gathering** | Collect and document business needs from stakeholders |
| **Problem Analysis** | Identify issues, gaps, and opportunities for improvement |
| **System Design** | Define how the system will meet business requirements |
| **Communication** | Act as a bridge between business stakeholders and technical teams |
| **Documentation** | Create SRS, diagrams, user stories, and technical specifications |
| **Feasibility Study** | Assess technical, economic, and operational feasibility |
| **Testing Support** | Assist in defining test cases and validating system functionality |
| **Project Coordination** | Collaborate with developers, testers, project managers, and clients |
| **Change Management** | Handle requirement changes and maintain traceability |

### Skills Required

| Skill Category | Specific Skills |
|----------------|-----------------|
| **Technical** | Understanding of databases, programming concepts, system architecture, UML diagrams |
| **Business** | Domain knowledge, process modeling, requirement elicitation, cost-benefit analysis |
| **Analytical** | Problem-solving, critical thinking, logical reasoning, attention to detail |
| **Interpersonal** | Communication (verbal and written), negotiation, conflict resolution, presentation |
| **Management** | Time management, prioritization, stakeholder management, facilitation |

### Role in Bridging Business and Technology

The System Analyst serves as the **translator and facilitator** between:

| Side | Focus |
|------|-------|
| **Business Side** | Goals, processes, needs, constraints, budget, timeline |
| **Technical Side** | Implementation, architecture, databases, code, infrastructure |

**Key bridging activities:**
- Convert business requirements into technical specifications
- Ensure technical solutions align with business goals
- Explain technical constraints to non-technical stakeholders
- Translate user needs into development tasks

## 12. System Development Life Cycle (SDLC)

### Project Phases:

| Phase | Key Question | Description |
|-------|--------------|-------------|
| **Planning** | Why build the system? | Feasibility study, scope definition, resource estimation, risk assessment, project approval |
| **Analysis** | Who, What, When, Where? | Requirement gathering, stakeholder analysis, process modeling, create SRS |
| **Design** | How will the system work? | Architecture design, database design, UI/UX design, component specification |
| **Implementation** | System delivery and deployment | Coding, testing, deployment, user training, system maintenance |

### SDLC Phase Outputs:

| Phase | Deliverable |
|-------|-------------|
| Planning | Project charter, feasibility report, project plan |
| Analysis | Software Requirements Specification (SRS), use case diagrams, data flow diagrams |
| Design | System architecture document, database schema, UI mockups, API specifications |
| Implementation | Working software, test cases, user manuals, deployment scripts |
